# Workoutly · Trabalho Final Mobile

- Responda em português. Ao concluir, explique o que mudou, por quê e como verificou.
- Trabalhe na cópia independente da disciplina. Consulte `README.md` e `docs/mobile-final/Requisitos.md` para executar e entender a entrega. Antes de mudar o escopo, leia `docs/backlog.md` e `docs/arquitetura.md`. Documentos acadêmicos na pasta superior são fontes somente para leitura.
- Faça o menor incremento completo. O app usa .NET 10, MAUI com XAML e code-behind, MVVM e SQLite no aparelho. Preserve as quatro telas, as três tabelas, o CRUD via DAO e o catálogo local. Guarde os dados em `FileSystem.AppDataDirectory`. Conta, servidor, sincronização, sessão de treino e professor ficam fora do escopo.
- Preserve a paleta, a fonte Inter e os recursos locais conforme `docs/identidade-visual.md`. Mantenha a confirmação de descarte e exclusão, os erros visíveis no formulário e a diferença entre lista vazia e erro de leitura. Use dados fictícios para testes e capturas.
- Verifique com `dotnet run --project tests/Workoutly.Local.Tests`. Compile iOS com `dotnet build src/Workoutly.Mobile/Workoutly.Mobile.csproj -f net10.0-ios -p:RuntimeIdentifier=iossimulator-arm64` e Android com `dotnet build src/Workoutly.Mobile/Workoutly.Mobile.csproj -f net10.0-android` quando o ambiente tiver os workloads. Rode os builds em sequência. Registre a plataforma e os limites em `docs/evidencias/`. Build e execução são verificações distintas.
- Use o vocabulário de `GLOSSARY.md`. Leia o `SKILL.md` aplicável em `.agents/skills`. Use `tdd` para novas regras com comportamento a testar, `diagnosing-bugs` para falhas difíceis e `code-review` para revisão solicitada. Use subagentes quando o usuário solicitar ou a skill exigir. Consulte `docs/skills.md` para origem das skills. Publicações, envios e mensagens externas exigem pedido explícito.
